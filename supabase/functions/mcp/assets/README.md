# M0 bundled assets and provenance

Generated/reproduced by `../spike/prepare-render.mjs`. `manifest.json` records
exact source URLs or repository paths, source/output SHA-256 digests and byte
sizes. Downloads are checked before being written; existing downloads are
verified and reused offline. Local sources are copied/decompressed afresh.

- `JetBrainsMono-Regular.ttf`: unchanged JetBrains Mono **v2.304**, SIL Open Font
  License 1.1; full notice in `JetBrainsMono-OFL.txt`. Source:
  <https://github.com/JetBrains/JetBrainsMono/tree/v2.304>.
- `GeistMono.ttf`, `FiraCode.ttf`, `Hack.ttf`: decompressed directly from the
  matching `public/fonts/*.woff2` files, not substituted upstream fonts. Font
  tables, glyph coverage, metrics and source timestamps are preserved. The
  repository Fira Code face is **Fira Code Light 5.002**; Geist Mono is **1.401**
  and Hack is **3.003**. Geist and Fira use SIL OFL 1.1 (full notices copied from
  the installed Fontsource packages). Hack's embedded full MIT/Bitstream Vera
  notice is extracted into `Hack-LICENSE.txt`. Each font's manifest entry links
  its license and records the exact conversion tool versions/options.
- `tailwind-beams.png`, `resend-dark.png`: byte-for-byte copies of the app's
  `public/brands/` backgrounds, used only for their corresponding presets.
  These identify third-party brands, do not imply endorsement, and do not
  acquire a new license by being copied here. See `public/brands/README.md`.
- `avatar-1.png`, `avatar-2.png`: original 32×32 pixel portraits generated by the
  preparation script, under this repository's MIT license. PNG bytes are embedded
  into SVG `<image>` patterns; no external avatar request is made at runtime.
- `parser-licenses.txt`: licenses for the installed parser packages whose exact
  `lumis.json` metadata/queries are copied into the generated adapter. Parser
  binaries themselves are **not** bundled and are fetched at runtime from pinned
  package URLs, with Lumis enforcing their SHA-256 metadata.
- `vendor-licenses.txt`: notices for the local browser JS prebundle (Lumis,
  themes, Tree-sitter and helpers, and Rolldown runtime). A duplicate is
  kept alongside the generated JS; this copy travels with the Edge static assets.

Generated app renderer modules remain under the repository's MIT license.
Lumis 0.9.0 and themes 0.4.0 are MIT-licensed; they are not upgraded by this spike.
`../spike/generated/vendor/vendor-manifest.json` records package versions, input
and output JS hashes. No resvg wrapper or rasterizer WASM is shipped: the MCP
produces SVG only, and clients perform optional rasterization locally.

## Reproduction

From the repository root, with Node, installed npm dependencies, Python >=3.11
and [uv](https://docs.astral.sh/uv/) available:

```sh
# Refresh just the three app font conversions, licenses and two brand images.
# Leaves generated app/vendor code and parser metadata/licenses untouched.
node supabase/functions/mcp/spike/prepare-render.mjs --assets-only

# Full preparation: same eight app modules, parser metadata, themes, avatars,
# fonts/images and browser vendor graph as before, plus the new brand assets.
node supabase/functions/mcp/spike/prepare-render.mjs

npx vitest run supabase/functions/mcp/spike/render-generation.test.ts
```

The asset-only mode requires the existing committed manifest and original M0
assets. Prefer it for brand-only refreshes: installed parser metadata can differ
from the committed snapshot (notably LLVM), and no parser update is intended.
Full preparation continues to reflect installed parser metadata without changing
its packaging algorithms.

`prepare-fonts.py` uses uv's isolated script environment with **fonttools==4.60.1**
and **brotli==1.1.0**, pinned in its inline dependency metadata. The first build
needs package-index access; cached subsequent builds can run offline. It clears
the WOFF2 flavor, disables timestamp/bounding-box recalculation, and saves with
stable table ordering. No Python/npm font dependency is added at Edge runtime.
Repeated preparation must leave asset bytes and manifest digests identical.

## Runtime contract

`loadFontBase64()` accepts exactly `/fonts/jetbrains-mono.woff2`,
`/fonts/geist-mono.woff2`, `/fonts/fira-code.woff2`, and `/fonts/hack.woff2`, but
returns **TTF** bytes encoded as base64. The generated renderer already emits
`data:font/ttf` and `format('truetype')`. Font reads and encoding are cached per
face; JetBrains' pre-existing TTF stays unchanged.

`loadImageDataUrl()` accepts exactly `/brands/tailwind-beams.png`,
`/brands/resend-dark.png`, `m0:avatar-1`, and `m0:avatar-2`, returning embedded PNG
data URLs. Arbitrary remote URLs, data URLs, other local paths, query strings and
traversal are rejected, without fetching anything. `assetBytes()` likewise only
reads the four font and four image basenames. Full emoji coverage remains out of
scope; this preserves the app font subsets rather than expanding them.
